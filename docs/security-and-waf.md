# 安全与 WAF

## 定位

内置 WAF 位于应用 HTTP 路由之前，用于降低随机不存在 URL、重复动态请求、搜索、XML-RPC 和附件下载对服务资源的消耗。它不是反向代理、CDN 或专业边缘 WAF 的替代品；生产环境仍应设置连接数、请求体、TLS 和网络层限制。

WAF 有总开关，各策略也可独立启停。配置从 `gb_options` 读取并在进程内缓存 5 秒，因此保存后短时间内可能仍有旧配置请求正在执行。

## 请求处理顺序

进程启动层先根据 `data/config.json` / `--allow-cidr` 检查 TCP 直接来源地址。不在允许网段内的请求直接返回 `403`，不会进入 WAF、插件或后台管理员白名单；该设置用于限制整个服务的网络暴露面，不属于可在后台修改的 WAF 规则。

通过启动层网段检查后，WAF 内部主要顺序为：

1. 加载 WAF 配置并安装安全响应头 writer。
2. 总开关关闭时直接进入应用，但安全响应头仍会应用。
3. 已登录管理员访问后台路径时绕过 WAF 限流/封禁；非 GET/HEAD 完成后使公开缓存失效。
4. 解析客户端 IP 并检查现有封禁；命中后统计该 IP 在封禁期间的请求，达到续期阈值时延长封禁，然后直接返回固定的纯文本状态信息，不再运行插件或查库。
5. 执行动态、静态或附件资源分类限流，以及搜索和 XML-RPC 专项限流。
6. 动态请求尝试获取全局和单 IP 并发槽位；容量耗尽时立即返回 `429`，不进入等待队列。
7. 执行 WAF 插件检查（`HookWAFCheck`），允许已启用插件参与 WAF 决策。
8. 对适用请求查询公开 URL 索引；不存在时统计无效路径并可能封禁，扩展路由使用同一份已缓存主题路由信息。
9. 对可缓存公开请求读取/写入响应缓存。
10. 对附件下载统计次数，达到阈值时封禁。
11. 进入实际路由；写请求完成后使公开索引和缓存失效。

理解顺序很重要：命中页面缓存前仍会经过 IP 封禁和限流；插件路由可绕过 URL 存在性检查，但不会绕过前面的频率限制。反向代理来源网段必须同时通过启动层 CIDR，后台的转发头信任设置才有机会生效。

## 管理员白名单边界

只有同时满足以下条件才绕过 WAF：

- 请求路径是 `/admin` 或 `/admin/...`。
- 当前会话有效。
- 用户角色至少为 `administrator`。

这不是按来源 IP 的永久白名单。管理员访问前台仍按公开请求处理，编辑和普通用户后台请求也不会获得同样的全局绕过。认证仍使用正常会话签名与用户 `authCode`，不能靠请求头声明管理员身份。

## 公开 URL 索引

URL 索引把实际存在的公开路径维护在内存集合中，随机不存在 URL 可在进入内容数据库详情查询前快速确认 404。公开 HTML 请求由当前主题的 `404.html` 输出错误页，索引仍会避免按随机 slug 查询内容详情。WAF 独立维护一份匿名主题 404 快照，不受普通页面缓存开关和 TTL 影响；公开数据、主题、插件或设置写入后才会失效重建。

索引在 HTTP 服务开始监听前完成首次构建，避免把冷启动成本交给第一批公网请求。正常 TTL 到期时只允许一个请求刷新，其他请求继续读取上一份完整索引，不会排队等待数据库查询。内容写入导致的主动失效仍会同步重建，避免新发布或修改的路径被旧索引误判。

索引包括首页、Feed、兼容接口、全部文章和页面固定链接、分类/标签及其 Feed、作者、归档、插件静态路由和插件登记的动态精确路径。内容使用分页构建完整索引，不会因条目上限把合法旧内容误判为 404。索引按 TTL 刷新，写操作会主动失效。

搜索、归档参数、预览、Trackback、后台和静态资源等需要特殊处理的路径不会简单按静态索引判断。任意伪造 Cookie 不会绕过索引；已签名登录态需要访问的私有内容路径也会登记到索引中，再由内容处理器执行权限判断。

新增核心公开路由时必须更新索引生成或排除规则，否则合法地址可能被提前返回 404。

## 公开响应缓存

内置缓存只缓存符合条件的公开 GET/HEAD 响应：

- 只保存 HTTP 200 且 body 非空的响应。
- 通过签名验证的登录态和未审核评论可见状态不进入普通公开缓存；无效或无关 Cookie 会从匿名缓存回源请求中移除。
- 带 `Set-Cookie` 的响应不能被当作公共页面复用。
- 搜索、列表页码和评论页码等内容参数进入规范化缓存键；跟踪参数和其他无业务意义参数被忽略，密码、回复、评论结果和预览参数不缓存。
- GET/HEAD 共享按路径和规范化查询参数生成的缓存键。
- 缓存响应生成 ETag，匹配 `If-None-Match` 时返回 304。
- 条目达到上限时按到期情况淘汰。
- 内容及后台写操作会使当前进程缓存失效。

相同缓存键首次并发回源时只允许一个请求渲染，其余请求等待该结果。缓存正常到期后会保留一个 TTL 的过期宽限期：一个请求负责刷新，刷新期间的其他请求直接使用上一份缓存，避免排队堆积和刷新完成后的集中响应。主动内容变更会清空缓存，不使用宽限期。单个响应在输出过程中只捕获配置允许的最大字节数，超过上限或设置了 `Set-Cookie` 时仍正常返回但不进入缓存；缓存同时受条目数和总内存限制。默认 TTL 为 30 秒、最大条目 512、单响应 512 KB、总正文内存 32 MB。缓存、计数和索引都在单进程内存中，多实例不会共享。

主题模板按“主题 + 页面模板”只解析一次，请求渲染时克隆模板并注入当前请求函数。最近文章、页面、分类、归档、标签、最近评论和用户资料使用同一份只读公共数据快照；内容、评论、设置、主题或插件写入成功后与页面缓存一并失效。最近评论查询直接按配置数量在 SQL 层限制，不再先读取固定的 200 条再截断。

后台、主题和插件静态资源默认带 24 小时浏览器缓存，上传资源默认带 1 小时缓存。应用本身不对动态响应执行 gzip，以免在单核机器上把压缩 CPU 与页面处理争抢；生产环境由 Nginx/CDN 完成压缩和连接缓冲。

## 分类限流

WAF 区分动态、普通静态和上传附件资源：

| 类别 | 典型路径 | 默认窗口/次数 |
|---|---|---|
| 动态请求 | 普通页面和应用请求 | 60 秒 / 300 次 |
| 静态资源 | `/admin/assets/`、主题与插件静态资源 | 60 秒 / 1200 次 |
| 上传资源 | `/uploads/` | 60 秒 / 600 次 |
| 搜索 | 搜索请求 | 60 秒 / 20 次 |
| XML-RPC | XML-RPC 请求 | 60 秒 / 30 次 |

每项均有独立开关、窗口和次数。分类频率计数按客户端 IP 和类别存储。限制设置得过低会影响正常页面加载，因为一个页面通常同时请求多个静态资源。

动态请求另有非阻塞并发准入，默认全局最多 16 个、单 IP 最多 4 个在途请求。槽位在插件检查、URL 索引、缓存回源和业务处理之前获取，请求结束后释放；容量耗尽时立即返回 `429` 和 `Retry-After: 1`，不会排队占用额外内存。该限制的目标是保护单核、低内存实例的进程和数据库，不保证过载期间所有正常请求都成功。

应用层并发准入不能减少已经由 Go 接受的 TCP 连接、HTTP 解析和拒绝响应成本。入口总连接数、平滑限速、代理缓存和静态资源直出仍应由 Nginx、CDN 或系统网络层承担。

内置 HTTP Server 对请求头、完整请求读取和响应写入分别设置 5 秒、30 秒和 60 秒上限，空闲连接保留 15 秒，避免慢请求无限占用并发槽位或文件描述符。大文件上传和慢速客户端下载应由前置代理缓冲；需要更长传输时间时，应在经过认证和限流的专用文件服务中处理，而不是取消整个应用的超时边界。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `waf_dynamic_concurrency_enabled` | 1 | 动态请求并发准入开关 |
| `waf_dynamic_concurrency_limit` | 16 | 全局动态请求在途上限 |
| `waf_dynamic_concurrency_per_ip` | 4 | 单 IP 动态请求在途上限 |

## 可用内存保护

可用内存保护是独立的进程安全能力，不受 WAF 总开关控制。它默认开启，最低可用内存默认为 50 MB。进程每 500 毫秒读取一次系统可用内存；Linux 容器环境还会读取 cgroup 内存限制，并使用宿主机可用内存与容器剩余额度中的较小值。Windows 使用系统物理内存状态，macOS 使用 Mach 虚拟内存统计。

可用内存低于阈值时，GopherInk 会立即关闭 HTTP 监听和现有连接，并以非零状态退出，不等待常规的 10 秒优雅关闭。这是避免整台低内存服务器因持续分配而失去响应的最后保护，不是流量限制策略。生产部署应由 systemd、Docker 或其他进程监管器负责重启，并配置合理的重启退避，避免阈值设置高于机器日常可用内存后形成重启循环。

设置项位于后台“设置 > 基本设置”页：

- `memory_guard_enabled`：是否启用，默认 `1`。
- `memory_guard_min_available_mb`：最低可用内存，单位 MB，最小 16，默认 `50`。

不支持读取可用内存的平台会在启动日志中说明并停用该保护。一次读取失败只记录日志，不会误杀进程；只有成功读取且明确低于阈值时才会退出。

## 附件下载封禁

附件下载封禁与普通上传资源限流独立。它按时间窗口内的附件请求次数统计，不按文件大小：

- 默认 60 秒内允许 120 次。
- 达到阈值后默认封禁 600 秒。
- 适用于防止反复请求大图片或下载文件消耗带宽。

按次数无法精确反映 Range 请求和真实字节量，反向代理/CDN 层仍应配置流量和并发限制。若附件通过对象存储域名直出，请在对象存储或 CDN 上配置对应策略，应用层 WAF看不到这些请求。

## 无效路径封禁

公开 URL 索引判定路径不存在时使用当前主题输出 HTTP 404，并按 IP 统计：

- 默认窗口 60 秒。
- 默认阈值 20 次。
- 默认封禁 600 秒。

此策略主要针对随机 URL CC。已启用插件路由和所有已编译主题通过 `Theme.Routes` 声明的有限路由会进入扩展路由快照，实际主题路由仍只由当前启用主题处理；运行时配置产生的路径由插件通过 `RegisterPublicPathProvider` 登记，因此正常扩展路由不会被索引当成非法路径。未登记的未知路径不会执行 `request.fallback` 插件钩子。`StaticProvider` 暴露的 `/plugin/<name>/` 资源按静态请求处理，不进入公开 HTML URL 索引。

并发请求同时越过首次封禁检查时，达到阈值后的请求仍会立即拦截，但只有真正创建封禁的请求记录一次触发事件。

## 活跃封禁续期

活跃封禁续期默认启用，策略参考入口 Nginx 的持续攻击续期方式：同一 IP 在有效封禁期间默认 10 秒内继续请求 3 次，就把封禁截止时间重置为“当前时间加该封禁原本的时长”。无效路径、附件下载、插件创建的运行时 IP 封禁和登录失败封禁都使用各自原本的封禁时长；每次续期后重新统计下一组命中。

续期命中窗口和计数严格按 IP 隔离。一个 IP 的持续攻击不会刷新其他 IP 的封禁，也不会建立全站封禁。每次实际续期最多按统计窗口写一条日志，普通封禁命中不逐请求写日志。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `waf_ban_extension_enabled` | 1 | 启用活跃封禁续期 |
| `waf_ban_extension_window` | 10 | 封禁期间请求统计窗口，单位秒 |
| `waf_ban_extension_hits` | 3 | 窗口内达到多少次封禁请求后续期 |

## 登录爆破防护

登录失败使用独立计数和封禁集合：

- 默认 300 秒窗口内允许 5 次失败。
- 触发后默认封禁登录 900 秒。
- 与普通请求封禁分开保存。

登录成功及具体计数清理按处理器逻辑执行。多实例部署时攻击者可轮换实例，因此还应在负载均衡器层进行统一限制。

## 反向代理 IP 信任

客户端 IP 默认来自 TCP 连接的 `RemoteAddr`。开启转发头信任后，只有直接连接的代理地址符合规则时，才按顺序读取 `X-Forwarded-For` 的第一个 IP或 `X-Real-IP`。

两种模式：

- `allowlist`：直接连接 IP 匹配地址组时才信任头。生产环境推荐。
- `denylist`：直接连接 IP 不匹配地址组时信任头，适合受控网络但边界更宽。

地址组一行一个 IPv4、IPv6 或 CIDR，空行和 `#` 开头的行忽略：

```text
127.0.0.1
10.0.0.0/8
2001:db8:1234::/48
```

若 GopherInk 可被公网直接访问，denylist 或过宽 CIDR 会允许伪造转发头。应在防火墙层只允许代理连接，并使用 allowlist 填写真实代理出口地址。

## 安全响应头和 HSTS

响应 writer统一设置：

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-XSS-Protection: 0`

HSTS 仅在请求为 TLS 且开关启用时发送：

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

只有主域和所有子域都长期稳定支持 HTTPS 时才启用。浏览器会在有效期内拒绝降级 HTTP，证书过期或子域不支持 HTTPS 时可能造成不可访问。

GopherInk 可以通过启动参数直接终止 TLS，也可以继续由反向代理终止 TLS。内置 TLS 的证书路径、私钥路径和监听端口属于 `data/config.json` 启动配置，不属于后台 WAF 设置；详细参数见 [安装与配置](installation-and-configuration.md#内置-httpstls)。

## WAF 日志

事件独立写入：

```text
data/waf.log
```

`GOPHERINK_DATA_DIR` 会改变其父目录。后台 WAF 的“日志”选项卡可滚动查看和清空。最大记录条目默认 1000，可配置 1 到 100000。频率事件按窗口去重，封禁命中不逐请求记录；日志超过上限后按小批次裁剪，避免每写一行都全量读取和重写文件。

日志可能包含客户端 IP和请求路径，应限制文件访问权限并纳入隐私和保留策略。不要通过前台静态目录暴露 `data/`。

插件可通过 Runtime 读取 WAF 统计，或写入/解除当前进程内的运行时 IP 封禁：

```go
func (Plugin) RuntimeHook(ctx context.Context, rt *plugin.Runtime, payload any) (any, error) {
    if rt.BanIP != nil {
        _ = rt.BanIP(ctx, "203.0.113.8", 30*time.Minute, "example plugin rule")
    }
    return payload, nil
}
```

该接口不会修改后台配置，也不会创建重启后仍存在的永久黑名单。需要长期生效的 IP 信誉库或规则库，应由插件自行保存，并在 `HookWAFCheck` 中重新应用。

## 状态容量

WAF 对页面缓存和计数状态设置最大条目，避免攻击者用不同 IP/路径无限增长内存。默认状态上限为 100000；公开 URL 索引只保存核心和扩展明确登记的真实路径，攻击请求不能向其中写入随机键。

公开 URL 索引和 WAF 配置刷新都使用单次回源和旧快照复用：正常到期时只有一个请求查询数据库，其他请求不等待刷新。路由响应后的 `request.after` 插件通知也有固定并发容量；容量耗尽时丢弃观测事件，而不是无限创建 goroutine。访问统计属于尽力而为的数据，不能反过来拖垮请求服务。

## 应用层边界与入口限流

IP 已被应用 WAF 封禁后，GopherInk 仍必须由操作系统接受连接，并由 Go 解析到足以识别客户端 IP 的 HTTP 请求。核心使用固定纯文本响应、无锁封禁热查询和日志去重压低单次成本，但无法像防火墙一样在数据包层静默丢弃流量。攻击工具持续复用连接时，即使每次处理很轻，仍可能占满 CPU；并发 TCP 连接对应的 socket、HTTP 缓冲区和 goroutine 也只能在连接进入进程后分配。

生产环境必须在 Nginx、CDN 或云防火墙设置入口请求频率和连接数上限，使超额请求在进入 GopherInk 前结束。Nginx 示例见项目 README 的“反向代理与 HTTPS”；直接暴露 GopherInk 端口时，应用 WAF只能保证进程内状态有界，不能代替网络层抗 DDoS 能力。

## SSRF 和外发请求

Pingback、Trackback发现等外发 HTTP 使用 `pkg/httpclient`：

- 只允许 HTTP/HTTPS。
- DNS 解析后拒绝回环、私网、未指定、多播和链路本地地址。
- 最多跟随 5 次重定向，并对重定向目标重复校验。
- 响应体有大小上限，默认 1 MB，并提供有限重试。

插件如果自行使用 `http.DefaultClient`，不会自动继承这些保护。访问用户提供 URL 时应复用安全客户端或实现等价校验。
